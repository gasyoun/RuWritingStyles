## 🧠 Dev Notes & Hypotheses (Bugs, ideas, context)

- Domain-derived weighting composes multiplicatively with an archetype override and, before v2.16.0, with two more mechanisms at once; the fix was to make a `DOMAIN_CLUSTER_WEIGHTS` row *authoritative* (replacing the generic ×1.5 rather than stacking) so a pair's authority is one auditable number. When adding a domain row, reproduce the multiplier that already fires unless a roadmap legislates otherwise, and remember weights reach the model only as prompt text — the mock provider ignores them, which is why the protected eval baseline cannot detect a weighting change.

- `evals/baselines/gold.json` is an enforceable contract, not a smoke artifact: absent baseline/candidate cases, a protected pass loss, or a lower aggregate pass rate must fail. New cases require the explicit `eval-promote` refresh path.
- **Adversarial cases score a *non*-edit, and all seven now say so mechanically.** `strict_fidelity` alone checks only that verification raised no warnings — a revision could rewrite the paragraph and still score; pinning `max_changed_line_ratio`/`max_char_delta_ratio` to `0.0` is what actually forbids the edit, and it is reachable (mock reports exactly 0.0). The four legacy cases were retrofitted in v2.18.0. One live caveat: `averintsev` is the only reviewing style with `review_mode.rewrite_allowed: true`, so its `0.0` bound is a case-level override of a style-level permission — deliberate (roadmap `L_ave_01` rules "Отклонить"), not an oversight.
- **A required finding type must exist in the reviewing style's `checks`, or the gate can never fire.** `oversimplification`, `missing_epistemic_markers` and `loss_of_philological_depth` existed only in `evals/manifest.json` — no passport declares them, so no reviewer could emit them and the four legacy adversarial cases were unpassable on every provider. `GOLD_PROTOCOL.md` already forbade this ("каждый тип находки в `required_finding_types` обязан существовать среди `checks`") but nothing enforced it; `tests/test_eval_adversarial_refusal_cases.py` now does, including a registry-coverage assertion so a new adversarial case cannot skip the contract. Aliases stay deliberately ungrounded — that is what lets a model reaching for the legacy label still score.
- CI exposes one stable branch-protection context, `CI / Required gate`; conditional Web/Obsidian jobs report `skipped` through that aggregator rather than making the required context disappear.
- The local editable Python installation points at the original checkout. In isolated worktrees, set `PYTHONPATH=src` (CI already does) so tests exercise the branch under review.
- v2.15.2 requires no database or run-artifact migration. Explicit run IDs and their collision error remain compatible; only automatically generated IDs change shape.
- v2.15.3 treats `run.json` as durable truth and SQLite as a rebuildable index; valid v2.15.2 manifests remain resumable through a conservative compatibility path.
- Provider budgets count at the HTTP-attempt boundary under a logical-call context: the first request consumes the logical attempt, while each retry and subsequent tool-loop HTTP turn consumes another attempt.
- Runtime assets remain canonical at repository top level. `setup.py` copies only the explicit allowlist into `ruwritingstyles/_runtime` during builds and verifies every copied SHA-256; installed workspaces receive editable copies, never implicit site-packages writes.
