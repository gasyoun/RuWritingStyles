# Кейс-стади фазы 1: прогон реальной статьи через конвейер

Дата: 2026-06-13. Завершает фазу 1 дорожной карты
[roadmap-sanskrit-dh.md](roadmap-sanskrit-dh.md) (пункт W6 плана
[implementation-plan-phase1.md](implementation-plan-phase1.md)).

Цель: прогнать настоящую русскоязычную статью по санскритологии через
детерминированный слой конвейера (линтер транслитерации, ГОСТ-библиография,
проверка цитирований, профиль журнала), измерить, что он ловит, и отделить
истинные срабатывания от ложных.

## Материал

Статья «Комментаторские стратегии русских переводчиков санскритского эпоса»
(М. Ю. Гасунс, рукопись, ~45 000 знаков, 77 прозаических сегментов). Сам текст —
неопубликованный черновик и хранится в приватном репозитории
[RuWritingStyles-corpus](https://github.com/gasyoun/RuWritingStyles-corpus);
здесь приводятся только агрегированные метрики и отдельные термины, не прозаические
фрагменты. Профиль целевого журнала — `vya` (Вопросы языкознания).

Прогон выполнен на провайдере `mock`: содержательный совет стилей при этом —
заглушка, но **детерминированный слой работает по-настоящему** и не зависит от
провайдера. Это и есть предмет замера.

## Что поймал детерминированный слой

### Линтер транслитерации (`rws lint-translit ... --journal vya`)

Первый прогон — 14 находок на 77 сегментах. После исправления двух ложных
правил (см. ниже) — **9 истинных находок**, схема транслитерации в тексте одна
(IAST), что хорошо:

| Тип | Кол-во | Оценка |
|---|---|---|
| `missing_iast_on_first_mention` | 7 | истинные: термины *веда, шлока, самаса, деванагари, брахмана, брахман, шастра* введены русской передачей без IAST при первом упоминании — нарушение требования `vya` (`ru+iast`). |
| `inconsistent_term_rendering` | 0 | в первом прогоне было 2 (*махабхарата, рамаяна*) — оказались ложными (см. ниже): эпические названия. |
| `mixed_transliteration_scheme` | 0 | Harvard-Kyoto в тексте нет. |
| `devanagari_nfc_issue` | 0 | деванагари в тексте нет. |

После всех правок остаётся **7 находок, все истинные** (точность 7/7 = 1.0):
линтер на этой статье срабатывает только на реальных нарушениях требования журнала.

### Профиль журнала (`vya`)

- **Объём: 45 008 / 40 000 знаков — превышение на 5 008.** Конкретное, действенное
  замечание: статью нужно сократить примерно на 11 % под лимит ВЯ.
- Список литературы: требуется ГОСТ Р 7.0.100-2018 (проверяется отдельно).
- Аннотация и ключевые слова — нужны на ru и en (в рукописи присутствуют).

### Проверка цитирований и ГОСТ-библиография

- Извлечено 4 библиографические ссылки: *Burba 2009, Erman 2009, Kazansky 2025,
  Syrkin 1992*. Все помечены как не найденные в структурной библиографии
  `knowledge/bibliography.json`.
- `references-gost.md` — пуст: ни одна ссылка статьи не сопоставлена с
  библиографией, поэтому в список литературы по ГОСТ попадать нечему.

Это **не** означало, что ссылки выдуманы. Прежнее ядро библиографии (26 записей)
не содержало источников именно этой статьи.

**Исправлено (2026-06-13).** `knowledge/bibliography.json` пополнен реальными
источниками статьи (18 записей: Бурба, Эрман, Гринцер, Кальянов, Васильков–Невелева,
Сыркин, Казанский, Лидова, Парибок ×2, Malhotra, Goldman ×2, Jhalakikar и три
сетевых корпуса; всего 44 записи). После пополнения все 4 извлечённые ссылки
**подтверждаются**, `references-gost.md` содержит корректный список по ГОСТ
(кириллица отсортирована первой):

```
1. Бурба Д. Бхагавадгита… — М. : РИПОЛ-классик, 2009.
2. Казанский Н. Н. Проблемы комментирования… // Индоевропейское языкознание
   и классическая филология. — 2025. — Т. 29. — С. 857–873.
3. Сыркин А. Я. Упанишады. В 3 кн.… — М. : Наука, 1992.
4. Эрман В. Г. Махабхарата. Книга шестая. Бхишмапарва… — М. : Ладомир, 2009.
```

Урок остаётся: ярлык `hallucination` при неполной библиографии **завышает
уверенность**. Ключ в `citations.json` сохранён ради совместимости (его читают
конвейер, eval-оценщик и кейс `gost-hallucinated-ref`), но текст `reason` уточнён —
«не найдено в библиографии; не обязательно выдумано».

## Ложные срабатывания → исправления

Прогон на живом тексте выявил два ложных правила; оба исправлены в этом же
коммите, с регрессионными тестами.

1. **`iast_in_cyrillic_word` на акронимных составных словах.** Слова вида
   `IAST-транслитерацией`, `TEI-схемы`, `XML-разметкой` помечались как смешение
   скриптов. Это латинский акроним + кириллическое слово через дефис, а не
   слитная ошибочная транслитерация. Аналогично легитимна запись
   `сноски-bhāṣya` (термин + IAST-глосса через дефис). Правило уточнено
   (`_has_fused_mixed_token`): срабатывание только если **один** дефисный
   под-токен сам смешивает кириллицу и латиницу (напр. слитное `бхāшья`).
   Эффект на статье: −5 ложных находок (5 → 0).

2. **`extract_citations` ловил `@gmail` из адреса почты.** Шаблон `@[\w-]+`
   (BibTeX-ключи) матчил домен в `gasyoun@gmail.com`. Добавлен отрицательный
   lookbehind `(?<!\w)`. Эффект: −1 ложная «галлюцинация» (5 → 4 настоящих).

3. **`inconsistent_term_rendering` на эпических названиях.** *Махабхарата*/*Рамаяна*
   помечались как непоследовательная передача, потому что в тексте есть и
   «Махабхарата» (кириллица), и *mahābhārata* (IAST-форма слова). Это имена
   собственные с устоявшейся русской передачей: обе формы корректны и выполняют
   разные функции. В `knowledge/sanskrit-terms.json` добавлено поле
   `proper_noun: true`; линтер исключает имена собственные из правил
   first-mention и consistency. Эффект на статье: −2 ложных находки (9 → 7).

## Что пока требует реального провайдера

Слой LLM-совета (review → council → revision → verification по стилям
Зализняк-очерк / Казанский / Лидова / Tronsky-Readings) на `mock` даёт заглушки.
Для содержательного прогона нужен ключ. На момент кейса:

- `anthropic` — ключа нет (`ANTHROPIC_API_KEY` не задан);
- `google` (gemini-2.0-pro) — **готов**;
- `openai` — ключа нет.

Содержательный совет — платный вызов на ~45 КБ неопубликованного текста, то есть
решение автора (стоимость + передача чернового текста во внешний сервис). Команда
для запуска, когда решение принято:

```bash
rws project-set-journal vya --project-dir .rws-project
rws run <article>.md --project-dir .rws-project --execute --provider google \
  --styles zalizniak-ocherk,kazanskiy-korpus,lidova-commentary,tronsky-readings
```

## Выводы для фазы 3 (золотой стандарт)

- Детерминированный слой даёт **воспроизводимую** разметку без ключей и без
  стоимости — пригоден как опорный сигнал в gold-протоколе.
- Реальный текст — лучший источник правил: один прогон дал три исправления
  линтера/экстрактора (акронимные составные, `@gmail`, эпические названия) и
  довёл точность на статье с ≈ 0.5 (7 из 14) до **1.0 (7 из 7)** — без потери
  ни одной истинной находки.
- Открытый пункт фазы 2: библиографическое ядро под конкретные статьи, иначе
  проверка цитирований не даёт сигнала (всё «не подтверждено»).

## Воспроизведение

```bash
# линтер (бесплатно, без провайдера)
rws lint-translit <article>.md --journal vya --json

# полный детерминированный прогон (mock)
rws project-set-journal vya --project-dir .rws-project
rws run <article>.md --run-id case --project-dir .rws-project --execute --provider mock
# смотреть: runs/case/translit-lint.json, citations.json, references-gost.md,
#           секцию «Соответствие журналу» в runs/case/report.md
```
