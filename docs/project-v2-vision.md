# RuWritingStyles: Видение Фазы F (Production Scale)

Этот документ суммирует ответы на стратегические вопросы по развитию платформы и описывает переход от локального инструмента к промышленному веб-сервису.

## 1. Филологическая таксономия: Москва vs Ленинград

На основе анализа [philology.ru](http://philology.ru/linguistics.htm) в систему внедрено различение региональных школ:

-   **Москва (МФШ)**: Акцент на системности, морфологической прозрачности и семантических полях (Апресян, Мельчук, Зализняк).
-   **Ленинград/Петербург (ЛФШ)**: Акцент на фонетической реальности, экспериментальной базе и историко-этимологическом реализме (Щерба, Бондарко, Тронский).

**Что сделано**:
-   Кластеры в `styles/manifest.yml` помечены тегами `location: Moscow/Leningrad`.
-   В `styles/archetypes.yml` добавлены новые архетипы Совета: **"Moscow Systemic Arbiter"** и **"Leningrad Realist Arbiter"**. Теперь пользователь может выбрать «региональную предвзятость» при разрешении споров.

## 2. Ответы на технические вопросы

### SQLite vs Файловая система (`runs/`)
**Выбор**: Переход на SQLite для индексации.
-   **Преимущество**: В режиме веб-сервиса SQLite позволяет мгновенно искать по метаданным («покажи все правки по теме etymology за прошлый месяц»), сортировать тысячи запусков и связывать их с пользователями. Файловая система остается для хранения «тяжелых» артефактов (промптов и полных текстов), но индекс должен быть в БД.

### Синхронный API vs Очередь задач (Job Queue)
**Выбор**: Job Queue (Celery/Arq/Redis).
-   **Преимущество**: Филологический аудит — тяжелая задача (17+ вызовов LLM). В синхронном режиме браузер может оборвать соединение по таймауту. Очередь задач позволяет пользователю нажать «Запустить», закрыть вкладку и вернуться позже, когда результат будет готов. Это критично для надежности веб-сервиса.

### Режим без внешних API (Privacy Mode)
**Решение**: Интеграция с локальными серверами типа **Ollama** или **vLLM**.
-   Для приватных текстов пользователь запускает локальную модель (например, Llama-3-70B) и прописывает её адрес в `.env` как `LOCAL_LLM_URL`. Система будет работать полностью в закрытом контуре.

## 3. Golden Eval Set (Золотой набор)

Для калибровки качества выбраны 5 документов Зализняка, покрывающих разные жанры и типы ошибок. В `evals/manifest.json` они помечены тегом `GOLD_ZALIZNYAK`:

1.  **pseudo-etymology**: Критика псевдометода (Заметки).
2.  **source-claim**: Работа с источниками и осторожность датировок (Очерк).
3.  **register-shift**: Соблюдение академического регистра (Школьников).
4.  **iesh-sound-law**: Проверка на знание фонетических законов (ИЭШ).
5.  **iesh-adversarial**: Защита «эпистемической осторожности» при агрессивной правке.

## 4. Профили пользователей

-   **Исследователь (по умолчанию)**: Получает полный спектр комментариев и обоснований, может оспаривать решения Совета.
-   **Редактор/Автор**: Режим «Быстрая правка» с минимальным количеством предупреждений, если время ограничено.
-   **Студент**: Режим «Обучающий», где каждое замечание сопровождается ссылкой на филологический первоисточник (например, на конкретную страницу Зализняка).
