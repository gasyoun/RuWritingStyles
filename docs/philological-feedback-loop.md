# Филологический Feedback Loop: Протокол обработки экспертных замечаний

Этот документ описывает стандарт интеграции внешней экспертной критики (рецензий, правок, комментариев Word) в систему RuWritingStyles.

## 1. Типология "Справедливых замечаний"

На основе анализа ревизии Е. А. Костиной выделены следующие категории системных ошибок:

| Код | Категория | Описание | Пример из замечаний |
|---|---|---|---|
| **META-1** | **Вводные конструкции** | Отсутствие метатекстовых связок. Непонятно, зачем приводится факт. | *"В примечании рассмотрен частный случай без всяких вводных слов."* |
| **ACAD-1** | **Академический этикет** | Имена ученых без инициалов, нарушение научной дистанции. | *"Фамилии без инициалов... маркер неуважения."* |
| **TERM-1** | **Терминологический долг** | Использование спецтермина без предварительного определения. | *"Термин без пояснения... рождает доп. вопросы."* |
| **ORDER-1** | **Логическая прецедентность** | Ссылка на факт, который еще не был введен в текст. | *"Эта информация должна идти раньше, до первого упоминания."* |
| **REG-1** | **Стилистический регистр** | Смещение в сторону разговорности или "устного сообщения". | *"Нормально для устного сообщения, для статьи - странно."* |

## 2. Алгоритм воспроизведения

Чтобы система начала учитывать эти замечания, необходимо:

1.  **Экстракция**: Извлечь комментарии из файла (`.docx` -> `comments.xml` -> `.md`).
2.  **Классификация**: Присвоить каждому замечанию код из таблицы выше.
3.  **Обновление Контракта**: Добавить соответствующие запреты/правила в `ClaudeStyles/zaliznyak-*.md`.
    *   *Пример:* Для **ACAD-1** добавить в промпт: "Всегда используй инициалы при упоминании исследователей (например, В. И. Кальянов, а не Кальянов)".
4.  **Unit-тест**: Создать в папке `tests/feedback/` фрагмент текста, провоцирующий ошибку, и убедиться, что новая версия промпта ее исправляет.

## 3. Интеграция в Совет (Council)

Замечания эксперта должны стать частью "Базы знаний" (Knowledge Base) для **Агента-Верификатора**. При финальной проверке текста он должен прогонять документ через чек-лист, сформированный по результатам Feedback Loop.
