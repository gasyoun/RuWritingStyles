# Контракт стиля

Контракт стиля нужен для того, чтобы `.md`-инструкция могла использоваться не только человеком в Claude Custom Style, но и автоматическим оркестратором.

## Принцип

Существующий файл в `ClaudeStyles/` остается главным текстовым описанием стиля. Машинный паспорт не заменяет его, а описывает:

- когда стиль применять;
- что он проверяет;
- чего он не должен делать;
- какие типы замечаний может выдавать;
- как он участвует в совете стилей.

## Минимальный паспорт

```yaml
id: zalizniak-zametki
name: Зализняк-заметки
source_prompt: ClaudeStyles/zalizniak-zametki-style.md
role: polemical_linguistic_reviewer
language: ru
best_for:
  - псевдоэтимологии
  - произвольные сближения слов
  - критика любительской лингвистики
checks:
  - unsupported_etymology
  - arbitrary_sound_change
  - accidental_similarity
  - weak_historical_inference
limits:
  - не заменяет источниковедческий аппарат
  - не должен превращать нейтральное объяснение в публицистику
review_mode:
  rewrite_allowed: false
  requires_span_ids: true
  output_format: findings_json
council:
  can_reply_to:
    - clarity
    - evidence
    - argument_structure
  should_defer:
    - factual_bibliography
    - manuscript_reading_without_source
```

## Поля паспорта

| Поле | Назначение |
|---|---|
| `id` | Стабильный технический идентификатор. |
| `name` | Человеческое название стиля. |
| `source_prompt` | Путь к существующему `.md`-файлу стиля. |
| `role` | Основная агентная роль. |
| `language` | Язык работы. |
| `best_for` | Ситуации, где стиль особенно полезен. |
| `checks` | Типы проблем, которые стиль умеет находить. |
| `limits` | Ограничения и зоны риска. |
| `review_mode` | Правила выдачи замечаний. |
| `council` | Правила участия в обсуждении замечаний. |

Текущая схема также поддерживает поля промышленного слоя:

| Поле | Назначение |
|---|---|
| `level` | `core`, `cluster` или `private`. |
| `cluster` | Родительский кластер для частного стиля, например `ling_iesh`. |
| `extends` | Наследование поведения от другого паспорта/кластера. |
| `domains` | Домены текста, где стиль получает больший вес. |
| `markers` | Лексические, синтаксические и эпистемические маркеры стиля. |
| `forbidden_edits` | Правки, которые агент не должен предлагать. |
| `anchors` | Регрессионные признаки, по которым проверяется стиль. |
| `conflict_priority` | Вес стиля в совете при конфликте школ. |

ID кластеров в актуальном manifest используют форму `ling_*` и `lit_*`; старые записи вида `cluster:mss` встречаются только в архивных roadmap-документах.

## Типы ролей

Первый набор ролей:

| Роль | Смысл |
|---|---|
| `systematic_grammar_reviewer` | Проверяет определения, классификации и грамматическую систему. |
| `polemical_linguistic_reviewer` | Ловит псевдологику и слабые языковые доказательства. |
| `source_critical_reviewer` | Проверяет источники, чтения, аппарат и осторожность вывода. |
| `clarity_reviewer` | Проверяет понятность для неспециалиста. |
| `commentary_reviewer` | Проверяет комментарий, перевод и семантический нюанс. |
| `cultural_context_reviewer` | Проверяет культурный контекст, традицию и гуманитарную интонацию. |

## Типы замечаний

Начальный словарь:

| Тип | Когда использовать |
|---|---|
| `unclear_definition` | Термин введен неясно или слишком поздно. |
| `weak_classification` | Классификация неполна или смешивает разные основания. |
| `unsupported_etymology` | Этимология не опирается на исторические формы. |
| `arbitrary_sound_change` | Предполагаемый звуковой переход произволен. |
| `accidental_similarity` | Сходство слов может быть случайным, но это не проверено. |
| `missing_source` | Нужен источник, датировка или указание корпуса. |
| `overstrong_conclusion` | Вывод сильнее, чем материал. |
| `unclear_for_reader` | Текст непонятен целевому читателю. |
| `style_overreach` | Стиль правки подавляет авторский голос или задачу. |

## Уровни серьезности

| Уровень | Смысл |
|---|---|
| `blocker` | Без исправления текст вводит в заблуждение. |
| `major` | Существенно страдает доказательство или понятность. |
| `minor` | Локальная правка улучшит текст. |
| `note` | Полезное наблюдение без обязательной правки. |

## Правило совместимости с `.md`

Паспорт не должен дублировать весь стиль. Он должен ссылаться на `source_prompt` и кратко описывать поведение для автоматизации.

Если между паспортом и `.md`-стилем есть конфликт, приоритет имеет `.md`-стиль как источник содержательного поведения. Паспорт нужно исправить.

## Что не входит в контракт

Контракт не должен хранить:

- длинные примеры письма;
- полный текст промпта;
- источниковые корпуса;
- настройки конкретного LLM-провайдера;
- секреты, ключи API или приватные пути.

Эти вещи должны жить отдельно.
