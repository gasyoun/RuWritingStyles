# PROTOCOL — H5010 same-judge candidate-order paired probe (preregistered)

_Created: 17-09-2026 · Last updated: 17-09-2026_

**Status: preregistered BEFORE any judgement call of this experiment.**
Preregistration commit SHA is recorded in `evals/probes/ORDER_PAIRED_h5010_2026-09-17.json`
(`protocol_commit`) and in the results artifact. Any post-hoc deviation must be
declared in the results artifact's `deviations` section.

Corrects the confounded H4658 position-swap inference ([PR #220](https://github.com/gasyoun/RuWritingStyles/pull/220)):
that pass compared judge C (`glm-5.3-flash`, reversed order) against rater B
(`claude-fable-5`, original order) — judge model AND candidate order changed
together, so the observed 0/25 flips cannot identify a position-only effect.
Verified 17-09-2026 from the recorded metadata in `raterC-h073gov-swap-2026-09-14.json`
(field `rater_c`) vs `raterB-h073gov.json` (field `rater_b`): the confound claim
holds; this protocol isolates order with a fixed judge.

## 1. Frozen inputs

- Sheet: `evals/annotation/sheet-h073gov.json`
  sha256 `8f92288f6595c3b49813c3e6f377a6c8c91c8b704e8791caaa3f22a184f42e62`
  (25 runs, frozen since 11-07-2026, unchanged by H4658 and by this probe).
- Items (25, canonical IDs = `run` field): `20260703-h073gov-{sanskrit-pseudo-etymology,karaka-not-padezh,vedic-classical-anachronism,samasa-misclassification,commentary-layer-mix}-r{01..05}`.
- Canonical candidate identities: per-run finding `id` fields (`finding-001`…),
  held in the mapping file, never shown to the judge; the judge sees only
  presented positions 1..n.
- Exclusions: **none** — all 25 items judged under both orders, including
  `vedic-classical-anachronism-r02` (the known typing miss; it is part of the
  paired signal, its human adjudication dossier stays authoritative per GOLD_PROTOCOL).

## 2. Fixed judge

- Judge: **GLM 5.3 Flash**, provider route `opencode/z-ai/glm-5.3-flash` — the
  SAME judge identity as H4658's rater C. Executor session and judge are the
  same model instance family (disclosed; the H4658 lane precedent: session-lane
  judging, no metered provider API calls). Judge is independent of the evaluated
  pipeline (the scored runs are deepseek `deepseek-v4-flash` outputs).
- Prompt/rubric: **verbatim rater B/C rubric**, three fields per item:
  - `caught` — "does any finding substantively identify the planted error from
    the case purpose" (yes/partial/no);
  - `type_correct` — "is a finding bearing the canonical required type (or a
    listed alias) aimed at the planted error" (true/false);
  - `false_positives` — "count of substantively spurious findings (misread the
    input); extra legitimate style-driven remarks are NOT counted" (int ≥ 0);
  - free-text `notes` for auditability.
  The judge receives per task: `input_text`, `purpose`,
  `required_finding_types`, `accepted_finding_aliases`, and the findings list
  with fields `position, type, severity, span_id, finding` (identity fields
  `id`, `style_id`, `council_status` stripped). Scorer verdicts and any earlier
  judgement files are withheld during judging.

## 3. Conditions, blinding, call order

- Two conditions per item: **A_original** (findings in frozen-sheet order) and
  **B_reversed** (list reversed, positions renumbered 1..n). Nothing else varies.
- Identity blinding: 50 task records with opaque ids `task-001…task-050`,
  generated by `tools/position_order_paired.py prep` with `SEED=5010`; the
  task→(run, condition) mapping is written to a separate file and NOT consulted
  until all 50 judgements are recorded. The judge does not learn which condition
  any task is.
- Randomized call order: the 50 tasks are judged strictly in file order
  (seeded shuffle), interleaving items and conditions.
- Decoding settings: session-lane default sampling; no temperature control is
  available on this lane — **stochasticity limitation**, disclosed in results;
  single pass per task (no best-of).
- Earlier judgements (rater B 11-07-2026, rater C 14-09-2026) are NOT reused as
  a condition arm: fixed conditions are not demonstrated equal (different judge
  for B; unblinded single-condition session for C). Both arms are judged fresh.

## 4. Budget and authorization

- Maximum **50 successful judgements** (25 items × 2 orders) + **5** redone
  judgements for transport/format errors. One judging pass; no pipeline
  re-execution.
- Monetary ceiling: **$0.00 metered spend** — session-subscription lane only,
  no provider API keys, no new paid calls (H4658 precedent, same lane). If any
  arm of this design had required metered API spend, the experiment would stop
  after protocol + offline controls + cost estimate and request the missing
  budget; it does not.

## 5. Analysis (fixed before unblinding)

Tool: `tools/position_order_paired.py reveal` (self-contained, stdlib, offline).

- Per item, a **discordant pair** = any of `caught` (label), `type_correct`
  (bool), `false_positives` (int) differing between A_original and B_reversed.
- Report: denominator (valid pairs), discordant count + list, flip rate, Wilson
  95% interval; ties/invalid verdicts counted with reasons; per-field flip
  breakdown.
- Directional first-position preference: for each condition-presentation, the
  presented position of the first canonical/alias finding vs verdict positivity
  (caught=yes or type_correct=true); medians and first-half/second-half counts;
  a selector is flagged `first_position_preference_detected` when positive
  verdicts concentrate at earlier target positions (median earlier AND higher
  early-share among positives than negatives).
- **Threshold (preregistered):** material order sensitivity = flip rate ≥ 0.20
  AND Wilson-95 lower bound > 0. Any discordant pair > 0 still counts as
  qualitative order sensitivity. **Zero flips is not proof of no bias** — with
  0/25 the Wilson-95 upper bound is ≈ 0.133 (reported explicitly), i.e. order
  sensitivity up to ~13% remains compatible with the data.
- Limitations stated in results: session-lane stochasticity (no temperature
  control, single pass); same judge sees both arms in one session (paired
  within-judge design; condition labels blinded, items interleaved); n=25.

## 6. Controls (offline, no model calls, `--selftest`)

- **Positive control:** synthetic known first-position selector
  (`selector_first_position`) must be detected: on the frozen sheet it produces
  exactly **16/25 discordant pairs** (the 9 items with canonical findings at
  BOTH ends are mathematically indistinguishable to a pure first-position
  selector under reversal), `first_position_preference_detected=true`, and
  `material_order_sensitivity_flag=true`. Assertions enforce this exactly.
- **Negative control:** order-invariant content-identity selector
  (`selector_content_identity`) must remain invariant after mapping presented
  positions back to candidate identities: **0/25 discordant**, no flags.
- Both controls run the SAME prep→reveal code path as the real analysis.
